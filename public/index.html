Playwright Interview Questions and Answers

Examples use TypeScript with @playwright/test.

Fundamentals

What is Playwright?

Playwright is an open-source browser automation framework. Playwright Test adds a test runner, assertions, fixtures, parallel execution, and reporting for end-to-end and other browser tests. It supports Chromium, Firefox, and WebKit. Official overview

1. What is the difference between Selenium and Playwright?

Both automate browsers, but Playwright provides built-in auto-waiting, browser contexts for isolated sessions, and a test runner with assertions and reporting. Selenium supports a broader range of browsers and languages, and uses the WebDriver standard. Choose based on your project’s browser, language, and infrastructure needs.

2. What are the advantages of Playwright?

  • Auto-waits for elements to be ready before acting.
  • Supports Chromium, Firefox, and WebKit.
  • Provides isolated browser contexts, parallel execution, retries, tracing, and screenshots.
  • Includes useful locators and retrying assertions.
  • Supports browser tests and API testing in one test framework.

3. Name some disadvantages of Playwright.

  • The team needs to learn its APIs and test runner.
  • Browser binaries and dependencies add setup requirements.
  • WebKit testing approximates Safari behavior but is not the same as running Apple Safari itself.
  • Some third-party integrations or browser-specific tooling may be less mature than alternatives.
  • Tests still need careful design; auto-waiting cannot fix unstable test data or application defects.

4. What testing types does Playwright support?

It is commonly used for end-to-end UI testing and API testing. Playwright also offers component testing for supported frontend frameworks. Teams can combine these with visual comparisons, accessibility checks, and cross-browser testing.

5. What programming languages does Playwright support?

The official Playwright libraries support JavaScript/TypeScript, Python, Java, and .NET (C#). Playwright Test is the JavaScript/TypeScript test runner.

Setup and test organization

6. What commands install Playwright and run tests?

npm init playwright@latest
npx playwright test

The setup command creates a starter project and can install browser binaries. Other useful commands:

npx playwright test --headed
npx playwright test --ui
npx playwright show-report

Installation and running tests

7. What is a configuration file in Playwright?

playwright.config.ts centralizes test settings such as test folders, browsers, base URL, timeouts, retries, workers, and reporters.

import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  testDir: './tests',
  use: {
    baseURL: 'https://example.com',
    ...devices['Desktop Chrome'],
  },
  reporter: 'html',
});

8. What is the @playwright/test package?

It is Playwright’s JavaScript/TypeScript test framework package. It includes the test runner, test and expect, fixtures, browser management, and reporting.

9. What is the Page class?

A Page represents one browser tab or popup. You use it to navigate, find elements, perform actions, and observe page events.

10. How do you navigate to a URL? Give a sample test.

Use page.goto():

import { test, expect } from '@playwright/test';

test('opens the home page', async ({ page }) => {
  await page.goto('https://example.com');
  await expect(page).toHaveTitle(/Example/);
  await expect(page).toHaveURL('https://example.com/');
});

11. What reporters does Playwright support?

Built-in reporters include list, line, dot, HTML, JSON, JUnit, blob, GitHub, and null. You can also write a custom reporter. Reporter documentation

12. What are locators? List five.

Locators find elements and are the recommended way to interact with them. They resolve against the current page state and support auto-waiting.

Five examples:

page.getByRole('button', { name: 'Save' });
page.getByText('Welcome');
page.getByLabel('Email');
page.getByPlaceholder('Enter email');
page.getByTestId('submit-button');

You can also use page.locator('css=...'). Locator documentation

13. What text selectors are available?

Common options include getByText('text'), getByText(/regular expression/), and locator('text=...'). Prefer getByText() for readable text-based queries; use role or label locators when they describe the element’s purpose more clearly.

Assertions and selectors

14. How do you use assertions? List five.

Import expect and await assertions. Locator assertions retry until they pass or time out.

await expect(page.getByRole('heading')).toBeVisible();
await expect(page.getByRole('button')).toBeEnabled();
await expect(page.getByText('Saved')).toHaveText('Saved');
await expect(page.getByLabel('Email')).toHaveValue('a@example.com');
await expect(page).toHaveURL(/dashboard/);

15. What are soft assertions?

Soft assertions record a failure but allow the test to continue. At the end, the test is still marked failed if any soft assertion failed.

await expect.soft(page.getByText('Profile')).toBeVisible();
await expect.soft(page.getByText('Settings')).toBeVisible();

16. How do you verify a “not” condition?

Use .not before the matcher:

await expect(page.getByText('Error')).not.toBeVisible();
await expect(page).not.toHaveURL(/login/);

17. Does Playwright support XPath? How do you use it?

Yes, but accessible locators such as role, label, or text are generally easier to maintain.

await page.locator('xpath=//button[@type="submit"]').click();

18. What are command-line options? Explain five helpful ones.

Options change which tests run or how they run. Examples:

  • --headed: show the browser window.
  • --project=chromium: run a configured browser project.
  • --grep "login": run tests whose titles match a pattern.
  • --workers=2: set the number of concurrent workers.
  • --ui: open the interactive test UI.

19. Mention some important command-line options.

Other useful options include --config, --debug, --last-failed, --retries, --timeout, --trace, --shard, --forbid-only, and --reporter. Check npx playwright test --help for the installed version’s options. CLI reference

20. What is headed and headless mode?

Headless mode runs without displaying a browser window and is the default. Headed mode displays the browser, which can help with debugging.

npx playwright test
npx playwright test --headed

21. Does Playwright support HTML reports? How do you generate one?

Yes. Configure the HTML reporter, run the tests, then open the report:

reporter: 'html',
npx playwright test
npx playwright show-report

22. What are timeouts? What types are available?

A timeout is the maximum time an operation or test can wait before failing. Common timeouts include:

  • Test timeout: maximum duration for a test.
  • Action timeout: limit for actions such as click().
  • Assertion timeout: limit for retrying an assertion.
  • Navigation timeout: limit for navigation operations.
  • Global timeout: maximum duration for the entire test run.

They can be set in the config or on relevant calls. Timeout guide

Browser navigation and interaction

23. How do you navigate forward and backward?

Use page.goBack() and page.goForward().

await page.goBack();
await page.goForward();

24. How do you perform actions?

Use locator methods such as click(), fill(), check(), selectOption(), and press().

await page.getByLabel('Email').fill('a@example.com');
await page.getByRole('button', { name: 'Submit' }).click();

25. Does Playwright support Safari?

Playwright supports WebKit, the browser engine used by Safari, and can run WebKit tests on supported platforms. That is useful for Safari-oriented coverage, but it is not the same as launching Apple’s Safari application. Browser support

26. How do you wait for a specific element?

Prefer a locator action or assertion, which waits automatically. For an explicit wait:

await page.getByRole('button', { name: 'Continue' }).waitFor({
  state: 'visible',
});

27. What is a browser context?

A BrowserContext is an isolated browser session with its own cookies, local storage, and pages. It lets tests run independently without launching a separate browser for every test.

28. How do you open multiple windows or tabs?

Each tab is a Page. To capture a new tab opened by an action:

const newPagePromise = page.context().waitForEvent('page');
await page.getByRole('link', { name: 'Open report' }).click();
const newPage = await newPagePromise;
await newPage.waitForLoadState();

29. How do you handle an iframe?

Use frameLocator() to locate and interact with elements inside the frame:

const frame = page.frameLocator('#payment-frame');
await frame.getByLabel('Card number').fill('4242424242424242');

Frames documentation

30. Explain click and double-click actions and options.

Use locator.click() and locator.dblclick(). Options include button, modifiers, position, clickCount, delay, and force. For example:

await page.getByText('Item').click({ button: 'left' });
await page.getByText('Item').dblclick();

force: true bypasses some actionability checks; use it only when you specifically need that behavior.

31. How do you right-click?

Set the button option to right:

await page.getByText('File').click({ button: 'right' });

32. How do you evaluate JavaScript?

Use page.evaluate() to run code in the page context:

const title = await page.evaluate(() => document.title);

Prefer user-facing interactions for normal tests; direct evaluation can bypass the UI behavior being tested.

Test data and browser features

33. What are Playwright fixtures?

Fixtures provide a test with the resources it needs and manage setup and cleanup. Built-in examples include page, context, browser, and request. You can also define custom fixtures. Fixtures guide

34. What is CodeGen?

CodeGen is a tool that records browser interactions and generates Playwright test code and locators.

npx playwright codegen https://example.com

35. How do you parameterize tests?

Use a data array and create a test for each case:

const users = ['alice', 'bob'];

for (const user of users) {
  test(`searches for ${user}`, async ({ page }) => {
    await page.goto('https://example.com');
    await page.getByRole('searchbox').fill(user);
    await page.getByRole('button', { name: 'Search' }).click();
  });
}

36. Write code to upload a file.

Use setInputFiles() on the file input:

await page.getByLabel('Upload file').setInputFiles('tests/fixtures/photo.png');

37. Write code to download a file.

Wait for the download event before clicking the download control:

const downloadPromise = page.waitForEvent('download');
await page.getByRole('link', { name: 'Download' }).click();
const download = await downloadPromise;
await download.saveAs(`downloads/${download.suggestedFilename()}`);

38. How do you perform drag and drop?

Use dragTo():

await page.getByText('Task A').dragTo(page.getByText('Done'));

39. How do you handle browser popups or dialogs?

Register a dialog handler before triggering the action:

page.on('dialog', dialog => dialog.accept());
await page.getByRole('button', { name: 'Delete' }).click();

For a popup window, wait for the context’s page event as shown in question 28.

40. What is the testInfo object?

testInfo contains details about the current test run, such as its title, status, retry number, attachments, output directory, and project configuration. It is available as a test callback parameter.

41. What is the testError object?

testError is not a standalone Playwright Test global. A test failure is represented by an error object, commonly available as testInfo.error after a failure or through reporter and fixture APIs. It contains information such as the error message and stack.

42. What are global setup and teardown?

Global setup runs once before the test suite, and global teardown runs once after it. They are configured with globalSetup and globalTeardown, often for tasks such as preparing shared test data. Use fixtures for resources that should be isolated per test.

Debugging, network, and screenshots

43. How do you capture network logs?

Listen for request and response events:

page.on('request', request => console.log('>>', request.method(), request.url()));
page.on('response', response => console.log('<<', response.status(), response.url()));

You can also use tracing for a richer record of a test run.

44. How do you capture screenshots?

Use page.screenshot() or locator.screenshot():

await page.screenshot({ path: 'screenshots/home.png', fullPage: true });

You can attach screenshots to a test report with testInfo.attach().

45. Does Playwright support API testing? How?

Yes. Use the request fixture to send API requests and assert on the response:

import { test, expect } from '@playwright/test';

test('gets a user', async ({ request }) => {
  const response = await request.get('https://api.example.com/users/1');
  expect(response.ok()).toBeTruthy();

  const user = await response.json();
  expect(user.id).toBe(1);
});

Visual tests, execution, and debugging

46. What is visual testing? Why is it useful?

Visual testing compares screenshots or visual snapshots to detect unintended changes to a page’s appearance. It can catch layout, styling, and rendering regressions that functional assertions may miss. Baselines can vary by browser, operating system, fonts, and rendering environment.

47. Write simple visual test code.

import { test, expect } from '@playwright/test';

test('home page looks correct', async ({ page }) => {
  await page.goto('https://example.com');
  await expect(page).toHaveScreenshot('home.png');
});

The first run may create a baseline; review it and use the project’s snapshot update workflow when intended changes occur. Visual comparisons

48. How do you configure multiple reporters?

Provide reporter entries in an array:

reporter: [
  ['list'],
  ['html', { open: 'never' }],
  ['junit', { outputFile: 'results.xml' }],
],

49. What is serial mode?

Serial mode runs tests in a group in order, typically in the same worker. If one test fails, later tests may be skipped and retries can rerun the group. It creates dependencies between tests, so independent tests are generally easier to maintain.

50. How do you perform parallel execution?

Playwright runs test files in parallel by default using worker processes. You can set workers in the config or on the command line:

npx playwright test --workers=4

Tests within a file can be made fully parallel with fullyParallel: true where appropriate.

51. How do you perform mobile device emulation?

Use a device descriptor in a Playwright project:

import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  projects: [
    {
      name: 'Mobile Chrome',
      use: { ...devices['Pixel 7'] },
    },
  ],
});

This configures settings such as viewport, user agent, and touch behavior. It emulates a device; it does not run tests on a physical phone.

52. Mention helpful ways to debug tests.

  • Run with --ui or --headed.
  • Use await page.pause() to open the Inspector during a run.
  • Run with --debug.
  • Capture a trace and inspect it with npx playwright show-trace.
  • Use screenshots, videos, and console or network event logs.
  • Check locator uniqueness and actionability when a test times out.

53. What is actionability in Playwright? Explain.

Before performing an action, Playwright checks that the target is in a suitable state. For a click, it checks that the locator resolves to one element and that the element is visible, stable, enabled, and able to receive events. Playwright waits for the relevant checks automatically; if they do not pass before the timeout, the action fails. This helps avoid timing-related failures. Actionability guide

54. What are some advantages of Playwright compared to Cypress?

Playwright supports Chromium, Firefox, and WebKit through one framework, and its browser contexts make isolated sessions and multiple pages straightforward. It also provides language bindings beyond JavaScript/TypeScript and supports API testing in Playwright Test. The best fit depends on the team’s existing tools, browser requirements, and preferred workflow.

Check the official documentation for exact option names and behavior in the version used by your project.

Selenium Interview Questions and Answers

1. What is Selenium?

Selenium is a widely used open-source tool for testing web applications and verifying their functionality. It is commonly used for cross-browser testing and web application automation.

  • Supports multiple browsers and operating systems.
  • Works with languages such as Java, Python, C#, and JavaScript.
  • Enables automated testing of web application functionality.

2. What are the Selenium suite components?

Here are four major components of Selenium:

  • Selenium IDE is a record-and-playback tool for creating and running automated tests for web applications. It allows users to record browser interactions and create test cases with minimal programming.
  • Selenium RC was an early Selenium tool that allowed automated browser testing through a server-based architecture. It has been deprecated and replaced by Selenium WebDriver.
  • Selenium WebDriver is the primary Selenium component used to automate web browsers. It provides APIs for interacting with browsers and supports multiple programming languages and browsers.
  • Selenium Grid enables tests to run across multiple machines, browsers, and operating systems, including parallel execution. Modern Selenium Grid supports distributed test execution and is no longer limited to the traditional Hub-Node architecture.

3. Mention the advantages of using Selenium as an automation tool.

Selenium offers several advantages that make it widely used for web application automation testing.

  • Selenium is freely available and supported by a large community.
  • Supports major browsers such as Chrome, Firefox, Edge, and Safari.
  • Works on operating systems such as Windows, Linux, and macOS.
  • Supports languages including Java, Python, C#, JavaScript, and Ruby.
  • Selenium Grid enables tests to run simultaneously across multiple browsers and environments.

4. What is test automation or automation testing?

Automated Testing is the process of using software tools and scripts to automatically execute test cases, validate results, and perform repetitive testing tasks.

  • Reduces manual effort and speeds up repetitive test execution.
  • Improves consistency and efficiency, especially for regression testing.
  • Commonly uses tools such as Selenium, Playwright, and Appium.

5. What are the advantages of automation testing?

Automation testing improves the efficiency and reliability of software testing by automating repetitive and time-consuming tasks.

  • Automation testing executes repetitive test cases quickly with minimal human intervention.
  • It increases test coverage by allowing more test cases and scenarios to be executed.
  • It reduces human errors by performing test steps consistently.
  • Reusable automated scripts make regression testing faster and easier.

6. What is Selenese? How is it classified?

Selenese is the set of commands used in Selenium IDE to create and execute automated test cases. These commands define the actions performed during browser automation and the validations used to check results.

Selenese commands are classified into three main categories:

  • Actions: Perform operations on web elements, such as clicking, typing, and selecting.
  • Assertions: Verify whether the actual result matches the expected result.
  • Accessors: Retrieve information from web elements, such as text, values, or attributes.

7. What is the difference between Selenium 2.0 and Selenium 3.0?

Selenium 2.0 streamlined creating automated tests for web applications by combining the original Selenium project with the WebDriver project. While Selenium Remote Control (RC) became outdated after the merge, it was still supported for a while to ensure existing tests wouldn’t break.

Building upon Selenium 2.0, Selenium 3.0 brought a range of improvements. It seamlessly worked with older tests while completely removing reliance on Selenium RC. This new version also squashed bugs and made everything more reliable.

In short, Selenium 3.0 took the strengths of Selenium 2.0, fixed its issues, and made it even better for automating web tests.

8. What are the testing types supported by Selenium?

Selenium mainly supports the following testing types:

  • Functional Testing: Verifies whether the application functions according to the specified requirements.
  • Regression Testing: Ensures that new updates or code changes do not affect existing features.
  • Cross-Browser Testing: Checks whether the application works properly across different web browsers.
  • UI Testing: Validates the appearance and behavior of user interface elements.
  • End-to-End Testing: Tests complete user workflows from beginning to end in the application.
  • Smoke Testing: Verifies whether the critical functionalities of the application are working correctly.
  • Data-Driven Testing: Executes the same test cases using multiple sets of input data.
  • Parallel Testing: Runs tests simultaneously on multiple browsers or machines using Selenium Grid.

9. What are the different types of annotations which are used in Selenium?

In Selenium automation, TestNG annotations are commonly used to control the setup, execution, and cleanup of test cases.

  • @BeforeSuite / @AfterSuite: Run before and after all tests in a TestNG suite.
  • @BeforeTest / @AfterTest: Run before and after the test methods associated with a <test> tag in the TestNG XML file.
  • @BeforeClass / @AfterClass: Run before and after the test methods in a class.
  • @BeforeMethod / @AfterMethod: Run before and after each test method.
  • @BeforeGroups / @AfterGroups: Run before the first and after the last test method of a specified group.
  • @Test: Marks a method as a test method to be executed by TestNG.

10. What are the types of Web locating strategies?

Selenium provides different locator strategies to identify and interact with web elements on a webpage.

Locating By ID: The ID locator identifies an element using its unique id attribute.

element = driver.find_element(By.ID, "element_id")

Locating By Class Name: The Class Name locator identifies elements using their class attribute. Multiple elements can have the same class name.

element = driver.find_element(By.CLASS_NAME, "element_class_name")

Locating By Name: The Name locator identifies elements using their name attribute and is commonly used for form elements.

element = driver.find_element(By.NAME, "element_name")

Locating By Tag Name: The Tag Name locator identifies elements using HTML tag names such as input, button, or a.

element = driver.find_element(By.TAG_NAME, "input")

Locating By CSS Selector: The CSS Selector locator identifies elements using CSS selectors based on attributes and the HTML structure.

element = driver.find_element(By.CSS_SELECTOR, "input.username")

Locating By XPath: XPath identifies elements by navigating through the webpage’s document structure.

element = driver.find_element(By.XPATH, "//input[@id='username']")

Locating By Link Text: Link Text identifies a hyperlink using its exact visible text.

element = driver.find_element(By.LINK_TEXT, "Login")

Locating By Partial Link Text: Partial Link Text identifies a hyperlink using part of its visible text.

element = driver.find_element(By.PARTIAL_LINK_TEXT, "Log")

11. What are the types of waits supported by WebDriver?

Selenium WebDriver provides three types of waits:

  • Implicit Waits: An implicit wait instructs WebDriver to wait for a specified time while polling the DOM when attempting to locate an element that is not immediately available.
  • Explicit Waits: An explicit wait waits for a specific condition to be satisfied before continuing with the next step. It is typically used for particular elements or conditions, such as visibility or clickability.
  • Fluent Wait: Fluent Wait provides greater control over waiting by allowing you to define the maximum timeout, polling interval, and exceptions to ignore while waiting for a condition.

12. Mention the types of navigation commands.

The Navigation Commands in Selenium WebDriver provide four methods: to(), back(), forward(), and refresh(). These methods allow WebDriver to perform browser navigation operations.

  • to() Command: Loads a new webpage in the current browser window. It accepts a URL as a parameter.
  • back() Command: Navigates one step back in the browser history. It does not accept any parameters.
  • forward() Command: Navigates one step forward in the browser history. It does not accept any parameters.
  • refresh() Command: Reloads the currently opened webpage in the browser. It does not accept any parameters.

15. What is an Absolute XPath and Relative XPath?

1. Absolute XPath

Absolute XPath specifies the complete path from the root element to the target element in the HTML or XML document. It always starts with a / symbol and follows the full hierarchy of elements.

/html/body/div/form/input

2. Relative XPath

Relative XPath identifies an element directly from anywhere in the document without starting from the root element. It usually starts with // and is more flexible and commonly used in Selenium.

//input[@id='username']

16. What are the limitations of Selenium testing?

Selenium is a powerful web automation tool, but it has certain limitations that may require additional tools or frameworks.

  • Selenium is primarily designed for automating web browsers and does not directly support desktop application testing.
  • Additional tools are often required for reporting, test management, and building a complete test automation framework.
  • Tasks such as CAPTCHA handling, some OS-level dialogs, and visual validation may require other tools or approaches.
  • Creating and maintaining Selenium automation scripts generally requires programming knowledge.

17. What is the same-origin policy and how is it handled?

The Same-Origin Policy is a browser security mechanism that restricts scripts from accessing resources from a different origin without permission.

  • An origin is defined by the combination of the protocol, domain, and port.
  • Cross-origin access can be allowed through mechanisms such as CORS (Cross-Origin Resource Sharing) when permitted by the server.
  • In Selenium testing, browser security restrictions should generally be handled through proper application or test-environment configuration rather than bypassing security controls.

Selenium is widely used for web application testing because it is flexible, accessible, and compatible with different technologies.

  • Selenium is open-source and supports multiple programming languages, making it accessible to testers and developers.
  • It supports major browsers such as Chrome, Firefox, Edge, and Safari for cross-browser testing.
  • It works across operating systems such as Windows, macOS, and Linux.

20. What is an exception test in Selenium?

In Selenium, an exception test is used when you expect a specific exception to occur during a test. If a test case is designed to throw a particular exception, you can use the @Test annotation in TestNG and specify the expected exception type in its parameters. This way, the test will pass only if that exception is thrown.

Example:

import org.testng.annotations.Test;

public class ExceptionTestExample {

    @Test(expectedExceptions = ArithmeticException.class)
    public void testDivideByZero() {
        int result = 10 / 0; // This line will throw an ArithmeticException
    }
}

In this example, the test will pass because an ArithmeticException is expected when dividing by zero. If no exception or a different exception is thrown, the test will fail.

21. How to wait until a web page has been loaded completely in Selenium?

In Selenium, you can use two main types of waits to ensure elements load before interacting with them:

  • Implicit Wait: Sets a basic wait time for all elements. Selenium will wait for this time before throwing an error if an element isn’t found.
  • Explicit Wait: Waits for a specific element or condition to be met, like waiting for a button to appear. This type of wait is more precise.

47. How can you handle multiple windows in Selenium?

When a new window is opened in Selenium, we must switch the WebDriver focus from the parent window to the child window. This is done using getWindowHandle() and getWindowHandles() methods. After switching, we can perform actions on the new window.

        driver.switchTo().window(window);
    }
}

// Now perform actions on child window
System.out.println(driver.getTitle());

// Switch back to parent window (optional)
driver.switchTo().window(parentWindow);

48. Explain Implicit and Explicit waits in Selenium.

Implicit Wait: Implicit wait is a global wait in Selenium that tells WebDriver to wait for a certain amount of time when trying to find any element. If the element is not immediately available, WebDriver keeps polling until the timeout is reached.

Explicit Wait: Explicit wait is used to wait for a specific condition to occur for a particular element before proceeding further. It is more flexible and applies only to selected elements.

50. How can we submit a form in Selenium?

This is how we can submit a form in Selenium:

1. Create a Form — we will create the form which we will be using to try submitting it from the Selenium script.

2. Code to Submit a Form — we will try to get the fields in which all the data will be entered. To get the field we can find it using Id, Class, or CSS Selector. In the following code block, we find the fields using ID and the submit button is tracked using the CSS Selector.

// Import necessary libraries
import org.openqa.selenium.Alert;
import org.openqa.selenium.By;
import org.openqa.selenium.WebDriver;
import org.openqa.selenium.WebElement;
import org.openqa.selenium.chrome.ChromeDriver;

public class Main {
    public static void main(String[] args) {
        // Set the path to the ChromeDriver executable
        System.setProperty("webdriver.chrome.driver", "path/to/chromedriver.exe");
        
        // Initialize WebDriver
        WebDriver driver = new ChromeDriver();

        // Navigate to the desired webpage
        driver.get("your-webpage-url"); // Replace with your actual webpage URL

        // Find the input fields using ID
        WebElement firstName = driver.findElement(By.id("FirstName"));
        WebElement dob = driver.findElement(By.id("DOB"));
        WebElement email = driver.findElement(By.id("Email"));
        WebElement inputNumber = driver.findElement(By.id("inputNumber"));
        WebElement maleRadioButton = driver.findElement(By.id("Male"));

        // Fill out the form
        firstName.sendKeys("Ram");
        dob.sendKeys("19-01-2001");
        email.sendKeys("ram@example.com");
        inputNumber.sendKeys("1234567890");
        maleRadioButton.click();

        // Click the submit button using CSS Selector
        driver.findElement(By.cssSelector("button[type='submit']")).click();

        // Switch to alert and get alert text
        Alert alert = driver.switchTo().alert();
        String alertText = alert.getText();

        // Check if the alert is open
        if (alertText != null) {
            System.out.println("Alert is open, and the content is: " + alertText);
            // Optionally accept the alert if needed
            // alert.accept();
        } else {
            System.out.println("No alert found.");
        }

        // Quit the browser
        driver.quit();
    }
}

54. What are the challenges of Parallel Execution in Selenium?

Parallel execution in Selenium helps reduce test execution time by running multiple tests simultaneously, but it introduces several challenges:

  • Test data conflicts: Multiple tests using the same data can interfere with each other.
  • Thread safety issues: WebDriver instances are not thread-safe without proper handling (e.g., ThreadLocal).
  • Resource contention: High CPU, memory, and network usage due to multiple browser instances.
  • Test dependency issues: Dependent tests may fail because execution order is not guaranteed.
  • Flaky tests: Race conditions and timing issues can lead to inconsistent results.
  • Difficult debugging: Hard to identify root cause when multiple tests run simultaneously.
  • Environment limitations: Limited infrastructure (Grid nodes/browsers) can restrict execution.

SQL Interview Questions and Answers

SQL Fundamentals

1. What is SQL?

SQL (Structured Query Language) is used to define, query, and manage data in relational databases.

2. What is a database?

A database is an organized collection of data that can be stored, accessed, and managed electronically.

3. What is a table?

A table stores data in rows and columns. Each row represents a record, and each column represents an attribute.

4. What is a primary key?

A primary key uniquely identifies each row in a table. It must contain unique, non-null values.

5. What is a foreign key?

A foreign key is a column or group of columns that references a key in another table. It helps maintain relationships between tables.

6. What is the difference between PRIMARY KEY and UNIQUE?

Both enforce uniqueness. A primary key identifies rows and cannot be null. A table has one primary key, though it can contain multiple columns. A table can have multiple unique constraints; how they treat NULL values depends on the database.

7. What are NULL values?

NULL represents missing or unknown data. It is not the same as zero or an empty string. Use IS NULL or IS NOT NULL to check it.

8. What is a constraint?

A constraint enforces rules on data in a table. Common constraints include PRIMARY KEY, FOREIGN KEY, UNIQUE, NOT NULL, and CHECK.

9. What is the difference between DELETE, TRUNCATE, and DROP?

  • DELETE removes selected rows and can use a WHERE clause.
  • TRUNCATE removes all rows from a table, with behavior varying by database.
  • DROP removes the table itself, including its structure.

10. What is the difference between CHAR and VARCHAR?

CHAR(n) stores fixed-length character data, while VARCHAR(n) stores variable-length data up to the specified limit. Exact storage behavior varies by database.

Querying Data

11. What do SELECT and FROM do?

SELECT specifies which columns or expressions to return. FROM specifies the table or source.

SELECT name, department
FROM employees;

12. How does the WHERE clause work?

WHERE filters rows before they are returned.

SELECT *
FROM employees
WHERE department = 'QA';

13. What is the difference between WHERE and HAVING?

WHERE filters rows before grouping. HAVING filters groups after GROUP BY.

SELECT department, COUNT(*) AS employee_count
FROM employees
GROUP BY department
HAVING COUNT(*) > 5;

14. What does ORDER BY do?

It sorts the result set. Use ASC for ascending order and DESC for descending order.

SELECT name, salary
FROM employees
ORDER BY salary DESC;

15. What does DISTINCT do?

DISTINCT removes duplicate rows from the selected columns.

SELECT DISTINCT department
FROM employees;

16. What are aggregate functions?

Aggregate functions calculate a value from multiple rows. Common examples are COUNT(), SUM(), AVG(), MIN(), and MAX().

17. What does GROUP BY do?

GROUP BY groups rows with matching values so aggregate functions can be calculated for each group.

SELECT department, AVG(salary) AS average_salary
FROM employees
GROUP BY department;

18. How do you search for a pattern in SQL?

Use LIKE with wildcards. % matches zero or more characters; _ matches one character. Case sensitivity depends on the database and collation.

SELECT *
FROM employees
WHERE name LIKE 'Sam%';

19. What does BETWEEN do?

BETWEEN checks whether a value falls within an inclusive range.

SELECT *
FROM employees
WHERE salary BETWEEN 50000 AND 80000;

20. How do you handle NULL in a query?

Use IS NULL or IS NOT NULL. To provide a substitute value, use COALESCE().

SELECT name, COALESCE(phone, 'Not provided') AS phone
FROM employees
WHERE manager_id IS NULL;

Joins and Subqueries

21. What is a join?

A join combines rows from two or more tables using a related column.

22. What is the difference between INNER JOIN and LEFT JOIN?

INNER JOIN returns rows that match in both tables. LEFT JOIN returns every row from the left table plus matching rows from the right; unmatched right-side values are NULL.

SELECT e.name, d.department_name
FROM employees e
LEFT JOIN departments d
  ON e.department_id = d.department_id;

23. What are RIGHT JOIN and FULL OUTER JOIN?

RIGHT JOIN returns all rows from the right table and matching rows from the left. FULL OUTER JOIN returns matched rows plus unmatched rows from both tables. Database support varies.

24. What is a self-join?

A self-join joins a table to itself, often to relate employees to their managers.

SELECT e.name AS employee, m.name AS manager
FROM employees e
LEFT JOIN employees m
  ON e.manager_id = m.employee_id;

25. What is a subquery?

A subquery is a query nested inside another query. It can be used in clauses such as SELECT, FROM, or WHERE.

SELECT name
FROM employees
WHERE salary > (
  SELECT AVG(salary)
  FROM employees
);

26. What is a correlated subquery?

A correlated subquery refers to columns from the outer query. It is evaluated in relation to each outer row.

27. What is the difference between IN and EXISTS?

IN checks whether a value matches a value in a list or query result. EXISTS checks whether a subquery returns any rows. The best choice can depend on the query, database, and data.

Data Changes and Database Design

28. What are INSERT, UPDATE, and DELETE used for?

  • INSERT adds rows.
  • UPDATE changes existing rows.
  • DELETE removes rows.
INSERT INTO employees (employee_id, name)
VALUES (101, 'Jordan');

UPDATE employees
SET name = 'Jordan Lee'
WHERE employee_id = 101;

DELETE FROM employees
WHERE employee_id = 101;

29. What is normalization?

Normalization organizes data to reduce unnecessary duplication and improve consistency. Common forms include 1NF, 2NF, and 3NF.

30. What is denormalization?

Denormalization intentionally duplicates or combines data to improve certain read workloads. It may make updates more complex and can introduce consistency risks.

31. What is an index?

An index is a data structure that can help a database find rows faster. Indexes can improve reads but use storage and may slow inserts, updates, and deletes.

32. What is a view?

A view is a saved query presented like a virtual table. It can simplify queries and control which data users see. A standard view does not necessarily store its results.

Transactions and Performance

33. What is a transaction?

A transaction is a group of database operations treated as one unit. A transaction can be committed to save changes or rolled back to undo them.

34. What are the ACID properties?

  • Atomicity: all operations in a transaction succeed or none do.
  • Consistency: the transaction preserves database rules.
  • Isolation: concurrent transactions are controlled to avoid interference.
  • Durability: committed changes persist.

35. What is the difference between COMMIT and ROLLBACK?

COMMIT saves a transaction’s changes. ROLLBACK undoes uncommitted changes.

36. What is a Common Table Expression (CTE)?

A CTE is a named query defined with WITH. It can make complex SQL easier to read and can be recursive in databases that support recursive CTEs.

WITH qa_employees AS (
  SELECT employee_id, name
  FROM employees
  WHERE department = 'QA'
)
SELECT *
FROM qa_employees;

37. What is a window function?

A window function calculates a value across related rows without collapsing them into one row per group. Examples include ROW_NUMBER(), RANK(), and SUM() OVER (...).

SELECT name, department, salary,
       RANK() OVER (
         PARTITION BY department
         ORDER BY salary DESC
       ) AS salary_rank
FROM employees;

38. What is the difference between UNION and UNION ALL?

Both combine results from compatible queries. UNION removes duplicate rows; UNION ALL retains them and is often faster.

39. How would you find duplicate values in a column?

SELECT email, COUNT(*) AS occurrences
FROM customers
GROUP BY email
HAVING COUNT(*) > 1;

40. How would you find the second-highest salary?

SELECT MAX(salary) AS second_highest_salary
FROM employees
WHERE salary < (SELECT MAX(salary) FROM employees);

This returns the second distinct salary. A window function such as DENSE_RANK() is useful when you need to return the employees who earn it.

41. How can you improve a slow SQL query?

Review the query plan, check that filters and joins use suitable indexes, return only needed columns, avoid unnecessary work, and confirm that the query matches the database’s schema and data distribution. Measure changes with representative data.

42. What is SQL injection, and how can you prevent it?

SQL injection happens when untrusted input is treated as part of a SQL command. Use parameterized queries or prepared statements instead of building SQL by concatenating input.

SQL features and syntax can vary between database systems such as PostgreSQL, MySQL, SQL Server, and Oracle.
