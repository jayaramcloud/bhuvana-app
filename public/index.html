Playwright Interview Questions and Answers

Examples use TypeScript with @playwright/test.

Fundamentals

What is Playwright?

Playwright is an open-source browser automation framework. Playwright Test adds a test runner, assertions, fixtures, parallel execution, and reporting for end-to-end and other browser tests. It supports Chromium, Firefox, and WebKit. Official overview

1. What is the difference between Selenium and Playwright?

Both automate browsers, but Playwright provides built-in auto-waiting, browser contexts for isolated sessions, and a test runner with assertions and reporting. Selenium supports a broader range of browsers and languages, and uses the WebDriver standard. Choose based on your project’s browser, language, and infrastructure needs.

2. What are the advantages of Playwright?

  • Auto-waits for elements to be ready before acting.
  • Supports Chromium, Firefox, and WebKit.
  • Provides isolated browser contexts, parallel execution, retries, tracing, and screenshots.
  • Includes useful locators and retrying assertions.
  • Supports browser tests and API testing in one test framework.

3. Name some disadvantages of Playwright.

  • The team needs to learn its APIs and test runner.
  • Browser binaries and dependencies add setup requirements.
  • WebKit testing approximates Safari behavior but is not the same as running Apple Safari itself.
  • Some third-party integrations or browser-specific tooling may be less mature than alternatives.
  • Tests still need careful design; auto-waiting cannot fix unstable test data or application defects.

4. What testing types does Playwright support?

It is commonly used for end-to-end UI testing and API testing. Playwright also offers component testing for supported frontend frameworks. Teams can combine these with visual comparisons, accessibility checks, and cross-browser testing.

5. What programming languages does Playwright support?

The official Playwright libraries support JavaScript/TypeScript, Python, Java, and .NET (C#). Playwright Test is the JavaScript/TypeScript test runner.

Setup and test organization

6. What commands install Playwright and run tests?

npm init playwright@latest
npx playwright test

The setup command creates a starter project and can install browser binaries. Other useful commands:

npx playwright test --headed
npx playwright test --ui
npx playwright show-report

Installation and running tests

7. What is a configuration file in Playwright?

playwright.config.ts centralizes test settings such as test folders, browsers, base URL, timeouts, retries, workers, and reporters.

import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  testDir: './tests',
  use: {
    baseURL: 'https://example.com',
    ...devices['Desktop Chrome'],
  },
  reporter: 'html',
});

8. What is the @playwright/test package?

It is Playwright’s JavaScript/TypeScript test framework package. It includes the test runner, test and expect, fixtures, browser management, and reporting.

9. What is the Page class?

A Page represents one browser tab or popup. You use it to navigate, find elements, perform actions, and observe page events.

10. How do you navigate to a URL? Give a sample test.

Use page.goto():

import { test, expect } from '@playwright/test';

test('opens the home page', async ({ page }) => {
  await page.goto('https://example.com');
  await expect(page).toHaveTitle(/Example/);
  await expect(page).toHaveURL('https://example.com/');
});

11. What reporters does Playwright support?

Built-in reporters include list, line, dot, HTML, JSON, JUnit, blob, GitHub, and null. You can also write a custom reporter. Reporter documentation

12. What are locators? List five.

Locators find elements and are the recommended way to interact with them. They resolve against the current page state and support auto-waiting.

Five examples:

page.getByRole('button', { name: 'Save' });
page.getByText('Welcome');
page.getByLabel('Email');
page.getByPlaceholder('Enter email');
page.getByTestId('submit-button');

You can also use page.locator('css=...'). Locator documentation

13. What text selectors are available?

Common options include getByText('text'), getByText(/regular expression/), and locator('text=...'). Prefer getByText() for readable text-based queries; use role or label locators when they describe the element’s purpose more clearly.

Assertions and selectors

14. How do you use assertions? List five.

Import expect and await assertions. Locator assertions retry until they pass or time out.

await expect(page.getByRole('heading')).toBeVisible();
await expect(page.getByRole('button')).toBeEnabled();
await expect(page.getByText('Saved')).toHaveText('Saved');
await expect(page.getByLabel('Email')).toHaveValue('a@example.com');
await expect(page).toHaveURL(/dashboard/);

15. What are soft assertions?

Soft assertions record a failure but allow the test to continue. At the end, the test is still marked failed if any soft assertion failed.

await expect.soft(page.getByText('Profile')).toBeVisible();
await expect.soft(page.getByText('Settings')).toBeVisible();

16. How do you verify a “not” condition?

Use .not before the matcher:

await expect(page.getByText('Error')).not.toBeVisible();
await expect(page).not.toHaveURL(/login/);

17. Does Playwright support XPath? How do you use it?

Yes, but accessible locators such as role, label, or text are generally easier to maintain.

await page.locator('xpath=//button[@type="submit"]').click();

18. What are command-line options? Explain five helpful ones.

Options change which tests run or how they run. Examples:

  • --headed: show the browser window.
  • --project=chromium: run a configured browser project.
  • --grep "login": run tests whose titles match a pattern.
  • --workers=2: set the number of concurrent workers.
  • --ui: open the interactive test UI.

19. Mention some important command-line options.

Other useful options include --config, --debug, --last-failed, --retries, --timeout, --trace, --shard, --forbid-only, and --reporter. Check npx playwright test --help for the installed version’s options. CLI reference

20. What is headed and headless mode?

Headless mode runs without displaying a browser window and is the default. Headed mode displays the browser, which can help with debugging.

npx playwright test
npx playwright test --headed

21. Does Playwright support HTML reports? How do you generate one?

Yes. Configure the HTML reporter, run the tests, then open the report:

reporter: 'html',
npx playwright test
npx playwright show-report

22. What are timeouts? What types are available?

A timeout is the maximum time an operation or test can wait before failing. Common timeouts include:

  • Test timeout: maximum duration for a test.
  • Action timeout: limit for actions such as click().
  • Assertion timeout: limit for retrying an assertion.
  • Navigation timeout: limit for navigation operations.
  • Global timeout: maximum duration for the entire test run.

They can be set in the config or on relevant calls. Timeout guide

Browser navigation and interaction

23. How do you navigate forward and backward?

Use page.goBack() and page.goForward().

await page.goBack();
await page.goForward();

24. How do you perform actions?

Use locator methods such as click(), fill(), check(), selectOption(), and press().

await page.getByLabel('Email').fill('a@example.com');
await page.getByRole('button', { name: 'Submit' }).click();

25. Does Playwright support Safari?

Playwright supports WebKit, the browser engine used by Safari, and can run WebKit tests on supported platforms. That is useful for Safari-oriented coverage, but it is not the same as launching Apple’s Safari application. Browser support

26. How do you wait for a specific element?

Prefer a locator action or assertion, which waits automatically. For an explicit wait:

await page.getByRole('button', { name: 'Continue' }).waitFor({
  state: 'visible',
});

27. What is a browser context?

A BrowserContext is an isolated browser session with its own cookies, local storage, and pages. It lets tests run independently without launching a separate browser for every test.

28. How do you open multiple windows or tabs?

Each tab is a Page. To capture a new tab opened by an action:

const newPagePromise = page.context().waitForEvent('page');
await page.getByRole('link', { name: 'Open report' }).click();
const newPage = await newPagePromise;
await newPage.waitForLoadState();

29. How do you handle an iframe?

Use frameLocator() to locate and interact with elements inside the frame:

const frame = page.frameLocator('#payment-frame');
await frame.getByLabel('Card number').fill('4242424242424242');

Frames documentation

30. Explain click and double-click actions and options.

Use locator.click() and locator.dblclick(). Options include button, modifiers, position, clickCount, delay, and force. For example:

await page.getByText('Item').click({ button: 'left' });
await page.getByText('Item').dblclick();

force: true bypasses some actionability checks; use it only when you specifically need that behavior.

31. How do you right-click?

Set the button option to right:

await page.getByText('File').click({ button: 'right' });

32. How do you evaluate JavaScript?

Use page.evaluate() to run code in the page context:

const title = await page.evaluate(() => document.title);

Prefer user-facing interactions for normal tests; direct evaluation can bypass the UI behavior being tested.

Test data and browser features

33. What are Playwright fixtures?

Fixtures provide a test with the resources it needs and manage setup and cleanup. Built-in examples include page, context, browser, and request. You can also define custom fixtures. Fixtures guide

34. What is CodeGen?

CodeGen is a tool that records browser interactions and generates Playwright test code and locators.

npx playwright codegen https://example.com

35. How do you parameterize tests?

Use a data array and create a test for each case:

const users = ['alice', 'bob'];

for (const user of users) {
  test(`searches for ${user}`, async ({ page }) => {
    await page.goto('https://example.com');
    await page.getByRole('searchbox').fill(user);
    await page.getByRole('button', { name: 'Search' }).click();
  });
}

36. Write code to upload a file.

Use setInputFiles() on the file input:

await page.getByLabel('Upload file').setInputFiles('tests/fixtures/photo.png');

37. Write code to download a file.

Wait for the download event before clicking the download control:

const downloadPromise = page.waitForEvent('download');
await page.getByRole('link', { name: 'Download' }).click();
const download = await downloadPromise;
await download.saveAs(`downloads/${download.suggestedFilename()}`);

38. How do you perform drag and drop?

Use dragTo():

await page.getByText('Task A').dragTo(page.getByText('Done'));

39. How do you handle browser popups or dialogs?

Register a dialog handler before triggering the action:

page.on('dialog', dialog => dialog.accept());
await page.getByRole('button', { name: 'Delete' }).click();

For a popup window, wait for the context’s page event as shown in question 28.

40. What is the testInfo object?

testInfo contains details about the current test run, such as its title, status, retry number, attachments, output directory, and project configuration. It is available as a test callback parameter.

41. What is the testError object?

testError is not a standalone Playwright Test global. A test failure is represented by an error object, commonly available as testInfo.error after a failure or through reporter and fixture APIs. It contains information such as the error message and stack.

42. What are global setup and teardown?

Global setup runs once before the test suite, and global teardown runs once after it. They are configured with globalSetup and globalTeardown, often for tasks such as preparing shared test data. Use fixtures for resources that should be isolated per test.

Debugging, network, and screenshots

43. How do you capture network logs?

Listen for request and response events:

page.on('request', request => console.log('>>', request.method(), request.url()));
page.on('response', response => console.log('<<', response.status(), response.url()));

You can also use tracing for a richer record of a test run.

44. How do you capture screenshots?

Use page.screenshot() or locator.screenshot():

await page.screenshot({ path: 'screenshots/home.png', fullPage: true });

You can attach screenshots to a test report with testInfo.attach().

45. Does Playwright support API testing? How?

Yes. Use the request fixture to send API requests and assert on the response:

import { test, expect } from '@playwright/test';

test('gets a user', async ({ request }) => {
  const response = await request.get('https://api.example.com/users/1');
  expect(response.ok()).toBeTruthy();

  const user = await response.json();
  expect(user.id).toBe(1);
});

Visual tests, execution, and debugging

46. What is visual testing? Why is it useful?

Visual testing compares screenshots or visual snapshots to detect unintended changes to a page’s appearance. It can catch layout, styling, and rendering regressions that functional assertions may miss. Baselines can vary by browser, operating system, fonts, and rendering environment.

47. Write simple visual test code.

  await page.goto('https://example.com');
  await expect(page).toHaveScreenshot('home.png');
});

The first run may create a baseline; review it and use the project’s snapshot update workflow when intended changes occur. Visual comparisons

49. What is serial mode?

Serial mode runs tests in a group in order, typically in the same worker. If one test fails, later tests may be skipped and retries can rerun the group. It creates dependencies between tests, so independent tests are generally easier to maintain.

50. How do you perform parallel execution?

Playwright runs test files in parallel by default using worker processes. You can set workers in the config or on the command line:

npx playwright test --workers=4

Tests within a file can be made fully parallel with fullyParallel: true where appropriate.

51. How do you perform mobile device emulation?

Use a device descriptor in a Playwright project:

import { defineConfig, devices } from '@playwright/test';

export default defineConfig({
  projects: [
    {
      name: 'Mobile Chrome',
      use: { ...devices['Pixel 7'] },
    },
  ],
});

This configures settings such as viewport, user agent, and touch behavior. It emulates a device; it does not run tests on a physical phone.

52. Mention helpful ways to debug tests.

  • Run with --ui or --headed.
  • Use await page.pause() to open the Inspector during a run.
  • Run with --debug.
  • Capture a trace and inspect it with npx playwright show-trace.
  • Use screenshots, videos, and console or network event logs.
  • Check locator uniqueness and actionability when a test times out.

53. What is actionability in Playwright? Explain.

Before performing an action, Playwright checks that the target is in a suitable state. For a click, it checks that the locator resolves to one element and that the element is visible, stable, enabled, and able to receive events. Playwright waits for the relevant checks automatically; if they do not pass before the timeout, the action fails. This helps avoid timing-related failures. Actionability guide

54. What are some advantages of Playwright compared to Cypress?

Playwright supports Chromium, Firefox, and WebKit through one framework, and its browser contexts make isolated sessions and multiple pages straightforward. It also provides language bindings beyond JavaScript/TypeScript and supports API testing in Playwright Test. The best fit depends on the team’s existing tools, browser requirements, and preferred workflow.

Selenium Interview Questions and Answers

1. What is Selenium?

Selenium is a widely used open-source tool for testing web applications and verifying their functionality. It is commonly used for cross-browser testing and web application automation.

  • Supports multiple browsers and operating systems.
  • Works with languages such as Java, Python, C#, and JavaScript.
  • Enables automated testing of web application functionality.

2. What are the Selenium suite components?

Here are four major components of Selenium:

  • Selenium IDE is a record-and-playback tool for creating and running automated tests for web applications. It allows users to record browser interactions and create test cases with minimal programming.
  • Selenium RC was an early Selenium tool that allowed automated browser testing through a server-based architecture. It has been deprecated and replaced by Selenium WebDriver.
  • Selenium WebDriver is the primary Selenium component used to automate web browsers. It provides APIs for interacting with browsers and supports multiple programming languages and browsers.
  • Selenium Grid enables tests to run across multiple machines, browsers, and operating systems, including parallel execution. Modern Selenium Grid supports distributed test execution and is no longer limited to the traditional Hub-Node architecture.

3. Mention the advantages of using Selenium as an automation tool.

Selenium offers several advantages that make it widely used for web application automation testing.

  • Selenium is freely available and supported by a large community.
  • Supports major browsers such as Chrome, Firefox, Edge, and Safari.
  • Works on operating systems such as Windows, Linux, and macOS.
  • Supports languages including Java, Python, C#, JavaScript, and Ruby.
  • Selenium Grid enables tests to run simultaneously across multiple browsers and environments.

4. What is test automation or automation testing?

Automated Testing is the process of using software tools and scripts to automatically execute test cases, validate results, and perform repetitive testing tasks.

  • Reduces manual effort and speeds up repetitive test execution.
  • Improves consistency and efficiency, especially for regression testing.
  • Commonly uses tools such as Selenium, Playwright, and Appium.

5. What are the advantages of automation testing?

Automation testing improves the efficiency and reliability of software testing by automating repetitive and time-consuming tasks.

  • Automation testing executes repetitive test cases quickly with minimal human intervention.
  • It increases test coverage by allowing more test cases and scenarios to be executed.
  • It reduces human errors by performing test steps consistently.
  • Reusable automated scripts make regression testing faster and easier.

6. What is Selenese? How is it classified?

Selenese is the set of commands used in Selenium IDE to create and execute automated test cases. These commands define the actions performed during browser automation and the validations used to check results.

Selenese commands are classified into three main categories:

  • Actions: Perform operations on web elements, such as clicking, typing, and selecting.
  • Assertions: Verify whether the actual result matches the expected result.
  • Accessors: Retrieve information from web elements, such as text, values, or attributes.

7. What is the difference between Selenium 2.0 and Selenium 3.0?

Selenium 2.0 streamlined creating automated tests for web applications by combining the original Selenium project with the WebDriver project. While Selenium Remote Control (RC) became outdated after the merge, it was still supported for a while to ensure existing tests wouldn’t break.

Building upon Selenium 2.0, Selenium 3.0 brought a range of improvements. It seamlessly worked with older tests while completely removing reliance on Selenium RC. This new version also squashed bugs and made everything more reliable.

In short, Selenium 3.0 took the strengths of Selenium 2.0, fixed its issues, and made it even better for automating web tests.

8. What are the testing types supported by Selenium?

Selenium mainly supports the following testing types:

  • Functional Testing: Verifies whether the application functions according to the specified requirements.
  • Regression Testing: Ensures that new updates or code changes do not affect existing features.
  • Cross-Browser Testing: Checks whether the application works properly across different web browsers.
  • UI Testing: Validates the appearance and behavior of user interface elements.
  • End-to-End Testing: Tests complete user workflows from beginning to end in the application.
  • Smoke Testing: Verifies whether the critical functionalities of the application are working correctly.
  • Data-Driven Testing: Executes the same test cases using multiple sets of input data.
  • Parallel Testing: Runs tests simultaneously on multiple browsers or machines using Selenium Grid.

9. What are the different types of annotations which are used in Selenium?

In Selenium automation, TestNG annotations are commonly used to control the setup, execution, and cleanup of test cases.

  • @BeforeSuite / @AfterSuite: Run before and after all tests in a TestNG suite.
  • @BeforeTest / @AfterTest: Run before and after the test methods associated with a <test> tag in the TestNG XML file.
  • @BeforeClass / @AfterClass: Run before and after the test methods in a class.
  • @BeforeMethod / @AfterMethod: Run before and after each test method.
  • @BeforeGroups / @AfterGroups: Run before the first and after the last test method of a specified group.
  • @Test: Marks a method as a test method to be executed by TestNG.

10. What are the types of Web locating strategies?

Selenium provides different locator strategies to identify and interact with web elements on a webpage.

Locating By ID: The ID locator identifies an element using its unique id attribute.

element = driver.find_element(By.ID, "element_id")

Locating By Class Name: The Class Name locator identifies elements using their class attribute. Multiple elements can have the same class name.

element = driver.find_element(By.CLASS_NAME, "element_class_name")

Locating By Name: The Name locator identifies elements using their name attribute and is commonly used for form elements.

element = driver.find_element(By.NAME, "element_name")

Locating By Tag Name: The Tag Name locator identifies elements using HTML tag names such as input, button, or a.

element = driver.find_element(By.TAG_NAME, "input")

Locating By CSS Selector: The CSS Selector locator identifies elements using CSS selectors based on attributes and the HTML structure.

element = driver.find_element(By.CSS_SELECTOR, "input.username")

Locating By XPath: XPath identifies elements by navigating through the webpage’s document structure.

element = driver.find_element(By.XPATH, "//input[@id='username']")

Locating By Link Text: Link Text identifies a hyperlink using its exact visible text.

element = driver.find_element(By.LINK_TEXT, "Login")

Locating By Partial Link Text: Partial Link Text identifies a hyperlink using part of its visible text.

element = driver.find_element(By.PARTIAL_LINK_TEXT, "Log")

11. What are the types of waits supported by WebDriver?

Selenium WebDriver provides three types of waits:

  • Implicit Waits: An implicit wait instructs WebDriver to wait for a specified time while polling the DOM when attempting to locate an element that is not immediately available.
  • Explicit Waits: An explicit wait waits for a specific condition to be satisfied before continuing with the next step. It is typically used for particular elements or conditions, such as visibility or clickability.
  • Fluent Wait: Fluent Wait provides greater control over waiting by allowing you to define the maximum timeout, polling interval, and exceptions to ignore while waiting for a condition.

12. Mention the types of navigation commands.

The Navigation Commands in Selenium WebDriver provide four methods: to(), back(), forward(), and refresh(). These methods allow WebDriver to perform browser navigation operations.

  • to() Command: Loads a new webpage in the current browser window. It accepts a URL as a parameter.
  • back() Command: Navigates one step back in the browser history. It does not accept any parameters.
  • forward() Command: Navigates one step forward in the browser history. It does not accept any parameters.
  • refresh() Command: Reloads the currently opened webpage in the browser. It does not accept any parameters.

15. What is an Absolute XPath and Relative XPath?

1. Absolute XPath

Absolute XPath specifies the complete path from the root element to the target element in the HTML or XML document. It always starts with a / symbol and follows the full hierarchy of elements.

/html/body/div/form/input

2. Relative XPath

Relative XPath identifies an element directly from anywhere in the document without starting from the root element. It usually starts with // and is more flexible and commonly used in Selenium.

//input[@id='username']

17. What is the same-origin policy and how is it handled?

  • In Selenium testing, browser security restrictions should generally be handled through proper application or test-environment configuration rather than bypassing security controls.

20. What is an exception test in Selenium?

In Selenium, an exception test is used when you expect a specific exception to occur during a test. If a test case is designed to throw a particular exception, you can use the @Test annotation in TestNG and specify the expected exception type in its parameters. This way, the test will pass only if that exception is thrown.

Example:

import org.testng.annotations.Test;

public class ExceptionTestExample {

    @Test(expectedExceptions = ArithmeticException.class)
    public void testDivideByZero() {
        int result = 10 / 0; // This line will throw an ArithmeticException
    }
}

In this example, the test will pass because an ArithmeticException is expected when dividing by zero. If no exception or a different exception is thrown, the test will fail.

  • Explicit Wait: Waits for a specific element or condition to be met, like waiting for a button to appear. This type of wait is more precise.

SQL Interview Questions and Answers

SQL Fundamentals

1. What is SQL?

SQL (Structured Query Language) is used to define, query, and manage data in relational databases.

2. What is a database?

A database is an organized collection of data that can be stored, accessed, and managed electronically.

3. What is a table?

A table stores data in rows and columns. Each row represents a record, and each column represents an attribute.

4. What is a primary key?

A primary key uniquely identifies each row in a table. It must contain unique, non-null values.

5. What is a foreign key?

A foreign key is a column or group of columns that references a key in another table. It helps maintain relationships between tables.

6. What is the difference between PRIMARY KEY and UNIQUE?

Both enforce uniqueness. A primary key identifies rows and cannot be null. A table has one primary key, though it can contain multiple columns. A table can have multiple unique constraints; how they treat NULL values depends on the database.

7. What are NULL values?

NULL represents missing or unknown data. It is not the same as zero or an empty string. Use IS NULL or IS NOT NULL to check it.

8. What is a constraint?

A constraint enforces rules on data in a table. Common constraints include PRIMARY KEY, FOREIGN KEY, UNIQUE, NOT NULL, and CHECK.

9. What is the difference between DELETE, TRUNCATE, and DROP?

  • DELETE removes selected rows and can use a WHERE clause.
  • TRUNCATE removes all rows from a table, with behavior varying by database.
  • DROP removes the table itself, including its structure.

10. What is the difference between CHAR and VARCHAR?

CHAR(n) stores fixed-length character data, while VARCHAR(n) stores variable-length data up to the specified limit. Exact storage behavior varies by database.

Querying Data

11. What do SELECT and FROM do?

SELECT specifies which columns or expressions to return. FROM specifies the table or source.

SELECT name, department
FROM employees;

12. How does the WHERE clause work?

WHERE filters rows before they are returned.

SELECT *
FROM employees
WHERE department = 'QA';

13. What is the difference between WHERE and HAVING?

WHERE filters rows before grouping. HAVING filters groups after GROUP BY.

SELECT department, COUNT(*) AS employee_count
FROM employees
GROUP BY department
HAVING COUNT(*) > 5;

14. What does ORDER BY do?

It sorts the result set. Use ASC for ascending order and DESC for descending order.

SELECT name, salary
FROM employees
ORDER BY salary DESC;

15. What does DISTINCT do?

DISTINCT removes duplicate rows from the selected columns.

SELECT DISTINCT department
FROM employees;

16. What are aggregate functions?

Aggregate functions calculate a value from multiple rows. Common examples are COUNT(), SUM(), AVG(), MIN(), and MAX().

17. What does GROUP BY do?

GROUP BY groups rows with matching values so aggregate functions can be calculated for each group.

SELECT department, AVG(salary) AS average_salary
FROM employees
GROUP BY department;

18. How do you search for a pattern in SQL?

Use LIKE with wildcards. % matches zero or more characters; _ matches one character. Case sensitivity depends on the database and collation.

SELECT *
FROM employees
WHERE name LIKE 'Sam%';

19. What does BETWEEN do?

BETWEEN checks whether a value falls within an inclusive range.

SELECT *
FROM employees
WHERE salary BETWEEN 50000 AND 80000;

20. How do you handle NULL in a query?

Use IS NULL or IS NOT NULL. To provide a substitute value, use COALESCE().

SELECT name, COALESCE(phone, 'Not provided') AS phone
FROM employees
WHERE manager_id IS NULL;

Joins and Subqueries

21. What is a join?

A join combines rows from two or more tables using a related column.

22. What is the difference between INNER JOIN and LEFT JOIN?

INNER JOIN returns rows that match in both tables. LEFT JOIN returns every row from the left table plus matching rows from the right; unmatched right-side values are NULL.

SELECT e.name, d.department_name
FROM employees e
LEFT JOIN departments d
  ON e.department_id = d.department_id;

23. What are RIGHT JOIN and FULL OUTER JOIN?

RIGHT JOIN returns all rows from the right table and matching rows from the left. FULL OUTER JOIN returns matched rows plus unmatched rows from both tables. Database support varies.

24. What is a self-join?

A self-join joins a table to itself, often to relate employees to their managers.

SELECT e.name AS employee, m.name AS manager
FROM employees e
LEFT JOIN employees m
  ON e.manager_id = m.employee_id;

25. What is a subquery?

A subquery is a query nested inside another query. It can be used in clauses such as SELECT, FROM, or WHERE.

SELECT name
FROM employees
WHERE salary > (
  SELECT AVG(salary)
  FROM employees
);

26. What is a correlated subquery?

A correlated subquery refers to columns from the outer query. It is evaluated in relation to each outer row.

27. What is the difference between IN and EXISTS?

IN checks whether a value matches a value in a list or query result. EXISTS checks whether a subquery returns any rows. The best choice can depend on the query, database, and data.

Data Changes and Database Design

28. What are INSERT, UPDATE, and DELETE used for?

  • INSERT adds rows.
  • UPDATE changes existing rows.
  • DELETE removes rows.
INSERT INTO employees (employee_id, name)
VALUES (101, 'Jordan');

UPDATE employees
SET name = 'Jordan Lee'
WHERE employee_id = 101;

DELETE FROM employees
WHERE employee_id = 101;

29. What is normalization?

Normalization organizes data to reduce unnecessary duplication and improve consistency. Common forms include 1NF, 2NF, and 3NF.

30. What is denormalization?

Denormalization intentionally duplicates or combines data to improve certain read workloads. It may make updates more complex and can introduce consistency risks.

31. What is an index?

An index is a data structure that can help a database find rows faster. Indexes can improve reads but use storage and may slow inserts, updates, and deletes.

32. What is a view?

A view is a saved query presented like a virtual table. It can simplify queries and control which data users see. A standard view does not necessarily store its results.

Transactions and Performance

33. What is a transaction?

A transaction is a group of database operations treated as one unit. A transaction can be committed to save changes or rolled back to undo them.

34. What are the ACID properties?

  • Atomicity: all operations in a transaction succeed or none do.
  • Consistency: the transaction preserves database rules.
  • Isolation: concurrent transactions are controlled to avoid interference.
  • Durability: committed changes persist.

35. What is the difference between COMMIT and ROLLBACK?

COMMIT saves a transaction’s changes. ROLLBACK undoes uncommitted changes.

36. What is a Common Table Expression (CTE)?

A CTE is a named query defined with WITH. It can make complex SQL easier to read and can be recursive in databases that support recursive CTEs.

WITH qa_employees AS (
  SELECT employee_id, name
  FROM employees
  WHERE department = 'QA'
)
SELECT *
FROM qa_employees;

37. What is a window function?

A window function calculates a value across related rows without collapsing them into one row per group. Examples include ROW_NUMBER(), RANK(), and SUM() OVER (...).

SELECT name, department, salary,
       RANK() OVER (
         PARTITION BY department
         ORDER BY salary DESC
       ) AS salary_rank
FROM employees;

38. What is the difference between UNION and UNION ALL?

Both combine results from compatible queries. UNION removes duplicate rows; UNION ALL retains them and is often faster.

39. How would you find duplicate values in a column?

SELECT email, COUNT(*) AS occurrences
FROM customers
GROUP BY email
HAVING COUNT(*) > 1;

40. How would you find the second-highest salary?

SELECT MAX(salary) AS second_highest_salary
FROM employees
WHERE salary < (SELECT MAX(salary) FROM employees);

This returns the second distinct salary. A window function such as DENSE_RANK() is useful when you need to return the employees who earn it.

41. How can you improve a slow SQL query?

Review the query plan, check that filters and joins use suitable indexes, return only needed columns, avoid unnecessary work, and confirm that the query matches the database’s schema and data distribution. Measure changes with representative data.

42. What is SQL injection, and how can you prevent it?

SQL injection happens when untrusted input is treated as part of a SQL command. Use parameterized queries or prepared statements instead of building SQL by concatenating input.

SQL features and syntax can vary between database systems such as PostgreSQL, MySQL, SQL Server, and Oracle.

Postman Interview Questions and Answers

Postman Basics

1. What is Postman?

Postman is a platform for building, sending, testing, and documenting API requests. It is commonly used to explore REST APIs and automate API checks.

2. What is an API?

An API (Application Programming Interface) lets software systems communicate through defined requests and responses.

3. What is an HTTP request?

An HTTP request is a message sent by a client to a server. It typically includes a method, URL, headers, and sometimes a body.

4. What are common HTTP methods?

  • GET retrieves data.
  • POST creates or submits data.
  • PUT replaces a resource.
  • PATCH updates part of a resource.
  • DELETE removes a resource.

5. What is an HTTP status code?

A status code tells the client the result of a request. For example, 200 means success, 201 means created, 400 indicates a client error, and 500 indicates a server error.

6. What is the difference between PUT and PATCH?

PUT generally replaces a resource, while PATCH updates selected fields. The exact behavior depends on the API’s design.

7. What is a Postman collection?

A collection is a group of saved requests. It can also contain folders, scripts, and shared configuration.

8. What is a Postman environment?

An environment is a set of variables for a particular context, such as development, QA, or production. It helps reuse the same requests with different URLs or credentials.

9. What is a request in Postman?

A request contains details such as the HTTP method, URL, parameters, headers, authorization, body, and scripts.

10. What is a response in Postman?

A response is what the server returns. Postman displays details including the status code, response body, headers, and response time.

Requests and Responses

11. What are query parameters?

Query parameters are values added to the end of a URL after ?. They are commonly used to filter, sort, or paginate results.

https://api.example.com/users?role=admin&page=2

12. What are path parameters?

Path parameters are part of the URL path and often identify a specific resource.

https://api.example.com/users/42

Here, 42 is the user ID.

13. What are headers?

Headers provide metadata about a request or response. Examples include Content-Type, Accept, and Authorization.

14. What is the request body?

The request body contains data sent to the server, commonly with POST, PUT, or PATCH requests. It may use JSON, form data, or another format supported by the API.

15. How do you send JSON in Postman?

Choose Body → raw → JSON, enter the JSON, and ensure the request uses the appropriate Content-Type: application/json header.

16. What is the difference between form-data and x-www-form-urlencoded?

Both send key-value form data. form-data uses multipart encoding and supports file uploads. x-www-form-urlencoded encodes fields into a URL-like format and is generally used for text fields.

17. What is the difference between response time and timeout?

Response time is how long a request took. A timeout is the maximum time Postman or a client waits before stopping the request.

18. What is a REST API?

A REST API follows REST architectural principles, typically exposing resources through URLs and using HTTP methods to read or change them.

19. What is the difference between REST and SOAP?

REST is an architectural style often used with JSON over HTTP. SOAP is a protocol with a formal message structure, usually XML. Both can support web services, but they differ in format and conventions.

20. What is GraphQL? Can Postman test it?

GraphQL is a query language and runtime for APIs that lets clients request specific fields. Postman can send GraphQL queries and mutations in a request body.

Authorization and Variables

21. What authentication methods can you configure in Postman?

Postman supports common methods such as Basic Auth, Bearer Token, API Key, OAuth 1.0, and OAuth 2.0. The API determines which method is required.

22. What is a Bearer token?

A bearer token is a credential sent with a request, commonly in the Authorization header:

Authorization: Bearer <token>

Anyone holding a valid bearer token may be able to use it, so it should be protected.

23. What are variables in Postman?

Variables store reusable values, such as a base URL, user ID, or token. They can be referenced in requests and scripts with double curly braces:

{{baseUrl}}/users

24. What are the main variable scopes?

Postman provides scopes such as global, collection, environment, data, and local. When the same variable name exists in multiple scopes, the more specific available scope takes precedence.

25. What is the difference between an environment variable and a collection variable?

An environment variable applies to a selected environment, such as QA or production. A collection variable is associated with a collection and can be used by its requests.

26. How do you set a variable from a response?

const body = pm.response.json();
pm.environment.set('userId', body.id);

The variable can then be used in later requests as {{userId}}.

Tests and Scripts

27. What are Postman scripts?

Scripts are JavaScript code that runs before a request or after a response. Pre-request scripts prepare data or authentication; post-response scripts can validate results or save values.

28. What is a pre-request script?

A pre-request script runs before the request is sent. It can set variables, generate timestamps, or prepare request data.

pm.variables.set('requestTime', new Date().toISOString());

29. What is a post-response script?

A post-response script runs after a response arrives. It is often used for assertions, extracting response values, and setting variables.

30. How do you test a response status code?

pm.test('Status code is 200', () => {
  pm.response.to.have.status(200);
});

31. How do you test a value in a JSON response?

pm.test('Response contains the expected name', () => {
  const body = pm.response.json();
  pm.expect(body.name).to.eql('Avery');
});

32. How do you check that a response contains a header?

pm.test('Content-Type header is present', () => {
  pm.expect(pm.response.headers.has('Content-Type')).to.be.true;
});

33. How do you check response time?

pm.test('Response is under 1 second', () => {
  pm.expect(pm.response.responseTime).to.be.below(1000);
});

34. What is the pm object?

pm is the Postman scripting API object. It provides access to the request and response, variables, tests, and other scripting features.

35. How do you parse a JSON response in a script?

const body = pm.response.json();
console.log(body);

36. How do you chain requests using a response value?

Save a value from one response to a variable, then use that variable in the next request.

const body = pm.response.json();
pm.environment.set('createdId', body.id);

Then use {{createdId}} in the next request’s URL or body.

Collections and Automation

37. What is the Collection Runner?

The Collection Runner executes requests in a collection or folder in sequence. It can run requests with an environment and data file.

38. What is Newman?

Newman is Postman’s command-line collection runner. It can run exported collections in scripts or continuous integration workflows.

39. How can you run a collection with Newman?

newman run collection.json -e environment.json

The collection and environment files must first be exported from Postman.

40. How do you use a data file with a collection run?

Provide a JSON or CSV file containing test data to the Collection Runner or Newman. Each row or data object can supply values to variables used by the requests.

41. How do you stop a collection from running a later request?

In a script, use pm.execution.setNextRequest(null) to stop the collection run. You can also set the next request by name or ID to control the sequence.

42. How do you skip a request during a collection run?

Use pm.execution.skipRequest() in a pre-request script when a condition means the request should not be sent.

43. What is a mock server in Postman?

A mock server returns example responses based on saved examples. It helps frontend or client development continue before the real API is ready.

44. What is API documentation in Postman?

Postman can generate and publish documentation from collections, including request details, parameters, examples, and authorization information.

45. What is a monitor in Postman?

A monitor runs a collection on a schedule and reports results. It can help check API availability and behavior over time.

API Testing Concepts

46. What is API testing?

API testing checks that an API behaves as expected, including its status codes, response data, headers, validation, error handling, and performance characteristics.

47. What should you validate in an API response?

Common checks include the status code, response body and schema, required fields, headers, response time, and expected behavior for invalid or unauthorized requests.

48. What is negative testing?

Negative testing checks how an API handles invalid or unexpected inputs, such as missing fields, malformed data, invalid IDs, or expired credentials.

49. What is schema validation?

Schema validation checks whether a response follows an expected structure and data types. Postman scripts can validate schemas using supported JavaScript libraries or explicit assertions.

50. What is the difference between authentication and authorization?

Authentication verifies who the caller is. Authorization determines what that caller is allowed to do.

51. What is idempotency?

An operation is idempotent if repeating the same request has the same intended effect as making it once. GET and PUT are generally designed to be idempotent; POST often is not.

52. What is pagination?

Pagination divides a large result set into smaller pages. APIs may use page numbers, offsets, cursors, or links to retrieve the next page.

53. What is rate limiting?

Rate limiting restricts how many requests a client can make in a given period. APIs may respond with a status such as 429 Too Many Requests when the limit is exceeded.

54. What is a 401 response? What is a 403 response?

401 Unauthorized usually means valid authentication credentials are missing or invalid. 403 Forbidden usually means the caller is authenticated but lacks permission. Exact API behavior may vary.

55. How would you test a login API in Postman?

Send a request with valid credentials and verify the success status, expected response fields, and token or session behavior. Then test invalid credentials, missing fields, and any relevant lockout or validation rules. Avoid storing real credentials in shared collections.

56. What are common causes of API test failures in Postman?

Common causes include an incorrect URL or method, missing headers, invalid authorization, malformed request data, incorrect environment variables, unavailable services, and assertions that do not match the API’s actual contract.

57. How do you protect secrets in Postman?

Avoid hard-coding credentials into shared requests or collections. Use appropriately scoped variables and secret management features available to your Postman setup, and avoid exposing tokens in logs or shared reports.

Postman’s interface and scripting APIs can change over time. For version-specific details, consult the Postman Learning Center.

Cypress Interview Questions and Answers

Examples use Cypress with JavaScript. Some features and command options depend on the Cypress version and project setup.

Cypress Basics

1. What is Cypress?

Cypress is a JavaScript-based testing framework for web applications. It is commonly used for end-to-end, component, and API testing.

2. What types of testing can Cypress perform?

Cypress supports end-to-end testing and component testing. It can also make HTTP requests for API checks and test application behavior at the network level.

3. Which browsers does Cypress support?

Cypress supports Chromium-based browsers, Firefox, and WebKit in supported configurations. Browser availability and behavior can vary by Cypress version and operating system.

4. What is the difference between Cypress and Selenium?

Cypress runs in a browser-oriented architecture and provides built-in retries, a test runner, screenshots, and debugging tools. Selenium uses the WebDriver protocol and supports a wider range of languages and browser automation setups.

5. What are some advantages of Cypress?

  • Automatic retrying for many commands and assertions.
  • Interactive test runner with time-travel snapshots.
  • Built-in screenshots, videos, and network stubbing.
  • Simple setup for JavaScript and TypeScript web projects.
  • Useful developer tools for debugging failures.

6. What are some disadvantages of Cypress?

  • Cypress tests are primarily written in JavaScript or TypeScript.
  • Some workflows involving multiple browser tabs or domains need special handling.
  • Browser and execution support differs from WebDriver-based tools.
  • Tests can become brittle if they rely on implementation details or fixed waits.

7. What is the Cypress Test Runner?

The Test Runner is Cypress’s interactive interface for running and debugging tests. It shows commands, snapshots, network activity, and errors as a test executes.

8. What is the Cypress Dashboard?

The Cypress Cloud service provides capabilities such as recorded test runs, parallelization, and run analytics, depending on the plan and configuration.

Setup and Test Structure

9. How do you install Cypress?

npm install --save-dev cypress

Open the Cypress app with:

npx cypress open

10. How do you run Cypress tests from the command line?

npx cypress run

To open the interactive runner:

npx cypress open

11. What is cypress.config.js or cypress.config.ts?

It is the Cypress configuration file. It can define the base URL, test file patterns, viewport, retries, timeouts, and event handlers.

import { defineConfig } from 'cypress';

export default defineConfig({
  e2e: {
    baseUrl: 'https://example.com',
  },
});

12. What is baseUrl?

baseUrl is the application’s root URL. Once configured, tests can use relative paths:

cy.visit('/login');

13. What is the structure of a Cypress test?

Tests use describe() to group cases, it() or specify() to define a case, and Cypress commands such as cy.visit() and cy.get() to interact with the app.

describe('Home page', () => {
  it('shows the page title', () => {
    cy.visit('/');
    cy.contains('Welcome').should('be.visible');
  });
});

14. What are fixtures in Cypress?

Fixtures are files that store reusable test data, often JSON. Load one with cy.fixture().

cy.fixture('user.json').then((user) => {
  cy.get('[name=email]').type(user.email);
});

Selectors and Assertions

15. How do you locate elements in Cypress?

Use cy.get() for CSS selectors and cy.contains() for text. Prefer stable selectors such as data-cy attributes.

cy.get('[data-cy="submit"]');
cy.contains('button', 'Save');

16. What are Cypress assertions?

Assertions verify that an expected condition is true. Cypress assertions retry until they pass or time out.

cy.get('[data-cy="status"]').should('have.text', 'Saved');

17. What is the difference between .should() and .and()?

Both add assertions to a Cypress command chain. .and() is an alias commonly used to add another assertion after .should().

cy.get('button')
  .should('be.visible')
  .and('be.enabled');

18. How do you assert that an element exists or is visible?

cy.get('[data-cy="message"]').should('exist');
cy.get('[data-cy="message"]').should('be.visible');

19. How do you verify that text appears on a page?

cy.contains('Welcome back').should('be.visible');

20. How do you check that a checkbox is selected?

cy.get('[data-cy="terms"]').check().should('be.checked');

21. How do you verify a negative condition?

cy.get('[data-cy="error"]').should('not.exist');
cy.get('[data-cy="spinner"]').should('not.be.visible');

Browser Interaction

22. How do you navigate to a page?

cy.visit('/dashboard');

23. How do you type into an input field?

cy.get('[name="email"]').type('person@example.com');

cy.get('[name="email"]').clear();

25. How do you select an option from a dropdown?

cy.get('select[name="country"]').select('Canada');

26. How do you hover over an element?

Cypress does not provide a native .hover() command. A common approach is to trigger relevant mouse events:

cy.get('[data-cy="menu"]').trigger('mouseover');

For applications that need full pointer movement, a plugin or another approach may be required.

27. How do you perform a right-click?

cy.get('[data-cy="item"]').rightclick();

28. How do you handle alerts and confirms?

Listen for browser events with cy.on():

cy.on('window:alert', (text) => {
  expect(text).to.equal('Saved');
});

cy.on('window:confirm', () => false); // dismiss the confirm

29. How do you work with iframes?

Cypress does not have a built-in iframe command. You can access the iframe’s document and wrap it, or use a maintained plugin. Cross-origin restrictions and iframe loading need consideration.

30. How do you upload a file?

Cypress does not include a universal built-in file-upload command in all setups. A common approach is the selectFile() command on a file input:

cy.get('input[type="file"]').selectFile('cypress/fixtures/sample.pdf');

31. How do you download a file?

Trigger the download, then check that the expected file exists in the configured downloads folder. The exact approach depends on the app and Cypress configuration.

Network and API Testing

32. What is cy.intercept()?

cy.intercept() spies on or stubs network requests. It can also assign an alias for waiting on a request.

cy.intercept('GET', '/api/users').as('getUsers');
cy.visit('/users');
cy.wait('@getUsers').its('response.statusCode').should('eq', 200);

33. How do you mock an API response?

cy.intercept('GET', '/api/users', {
  statusCode: 200,
  body: [{ id: 1, name: 'Avery' }],

cy.visit('/users');
cy.wait('@getUsers');

34. How do you make an API request directly?

Use cy.request():

cy.request('GET', '/api/users').then((response) => {
  expect(response.status).to.eq(200);
});

35. What is the difference between cy.request() and cy.intercept()?

cy.request() sends an HTTP request directly from the test. cy.intercept() observes, modifies, or stubs network traffic made by the application.

36. How do you test a POST API request?

cy.request('POST', '/api/users', {
  name: 'Avery',
  role: 'QA',
}).then((response) => {
  expect(response.status).to.eq(201);
  expect(response.body.name).to.eq('Avery');

Variables, Hooks, and Test Data

37. What are Cypress custom commands?

Custom commands extend Cypress’s cy command interface with reusable operations, such as logging in or opening a common page.

38. What are hooks in Cypress?

Hooks run setup or cleanup code around tests. Common hooks include before(), beforeEach(), afterEach(), and after().

beforeEach(() => {
  cy.visit('/login');
});

39. How do you share data between Cypress commands?

Cypress commands are queued and yield values asynchronously. Use .then() to access a yielded value and continue the chain.

cy.get('[data-cy="username"]').invoke('text').then((username) => {
  expect(username).to.contain('Avery');
});

40. What is a Cypress alias?

An alias gives a name to a subject, fixture, or intercepted request. Define it with .as() and access it with cy.get('@name') or cy.wait('@name').

cy.intercept('GET', '/api/orders').as('getOrders');
cy.wait('@getOrders');

41. How do you parameterize tests?

Use a data array and iterate over it:

['admin', 'editor'].forEach((role) => {
  it(`shows the page for ${role}`, () => {
    cy.visit(`/dashboard?role=${role}`);
    cy.get('[data-cy="dashboard"]').should('be.visible');
  });

npx cypress run --spec "cypress/e2e/login.cy.js"

45. What are screenshots and videos in Cypress?

Cypress can capture screenshots on failure and record videos during a cypress run, depending on the project configuration and version.

46. How do you debug a Cypress test?

Use the interactive Test Runner, inspect command snapshots and browser DevTools, add .debug() or cy.pause(), and review screenshots, videos, and logs.

47. What is test retrying in Cypress?

Cypress can rerun failed tests a configured number of times. Retries may help identify flaky behavior, but they do not replace fixing unreliable tests or application behavior.

48. What is test isolation?

Test isolation means each test starts in a clean state, such as a fresh page and cleared browser state, according to Cypress configuration. It helps prevent tests from depending on each other.

49. How can Cypress tests run in parallel?

Parallelization is available through Cypress Cloud for supported plans and configurations. Tests can be split across CI machines, with the Cloud coordinating spec distribution and reporting.

50. What is the Cypress command queue?

Cypress commands are enqueued and executed later in order. They are not ordinary synchronous JavaScript promises, so commands should be chained or handled with Cypress’s .then().

More Advanced Questions

51. What is cross-origin testing in Cypress?

Cross-origin testing involves visiting or interacting with a different origin. Modern Cypress supports certain cross-origin flows using cy.origin(), but the test must follow Cypress’s rules for origin boundaries.

52. What is cy.origin() used for?

It runs Cypress commands in the context of a specified origin, often for authentication flows that move between domains.

cy.origin('https://login.example.com', () => {

53. What is component testing in Cypress?

Component testing mounts an individual UI component in a real browser and tests its behavior independently from the full application.

54. What is the Page Object Model?

The Page Object Model organizes page selectors and actions into reusable classes or objects. It can reduce duplication, but page objects should stay focused and avoid hiding test intent.

55. What is a flaky test? How can you reduce flakiness?

A flaky test sometimes passes and sometimes fails without a relevant code change. Use stable selectors, wait for meaningful conditions, control test data, avoid fixed sleeps, and isolate tests from one another.

56. What is the difference between cy.wait(5000) and waiting on an alias?

cy.wait(5000) pauses for a fixed duration and may be unnecessarily slow or still too short. cy.wait('@requestAlias') waits for a specific network request, making the test more purposeful.

57. How do you handle authentication efficiently in Cypress?

For tests that do not need to verify the login flow itself, use a supported session strategy such as cy.session() to cache and restore authentication state. Keep separate tests that verify login behavior.

58. What is cy.session()?

cy.session() caches and restores browser session data, such as cookies and local storage, to avoid repeating login setup in every test.

59. How should test data be managed?

Use controlled test data through fixtures, API setup, or dedicated test environments. Make tests independent and clean up data when needed.

60. What are common causes of Cypress test failures?

Common causes include unstable selectors, incorrect test data, app timing issues, missing network waits, environment problems, cross-origin handling, and tests that depend on execution order.

Appium Fundamentals

1. What is Appium?

Appium is an open-source automation platform for testing mobile apps. It uses the WebDriver protocol and supports native, hybrid, and mobile web applications.

2. What kinds of apps can Appium test?

Appium can automate native apps, hybrid apps that combine native and web views, and mobile websites in supported browsers.

3. Which platforms does Appium support?

4. Which programming languages can be used with Appium?

5. What is the difference between Appium and Selenium?

Selenium primarily automates web browsers. Appium builds on WebDriver concepts to automate mobile apps and devices through platform-specific drivers. Appium can also automate mobile browsers.

6. What are the advantages of Appium?

  • Supports Android and iOS automation with a common WebDriver model.

8. How does Appium work?

10. What is the UiAutomator2 driver?

UiAutomator2 is a commonly used Appium driver for Android automation. It supports native and hybrid app testing and uses Android automation tools under the hood.

26. How do you enter text?

driver.findElement(AppiumBy.accessibilityId("email"))
      .sendKeys("person@example.com");

27. How do you hide the keyboard?

Use the client’s supported keyboard-hide command, if available, or interact with a visible control that dismisses it. The exact API can vary by client and platform.

28. How do you scroll in Appium?

Use platform-supported mobile gestures or the client’s W3C Actions APIs. Gesture syntax and support depend on the driver and client version. Avoid relying on deprecated platform-specific commands where possible.

29. How do you perform a swipe?

Use a touch or pointer action sequence through the client’s supported actions API, or a driver-supported gesture method. Coordinates should account for screen size and orientation.

30. How do you handle alerts or permission dialogs?

Use the driver’s supported alert commands when the dialog is exposed as a native alert. For system permission prompts, locate and interact with the dialog’s UI elements. Behavior varies by platform and OS version.

Native, Hybrid, and Web Contexts

31. What is a native app?

A native app is built for a platform using its native frameworks and UI components.

32. What is a hybrid app?

A hybrid app combines native app elements with web content, often displayed inside a WebView.

33. What is a context in Appium?

A context represents an automation mode available in a session. Native apps commonly use a NATIVE_APP context; hybrid apps may expose one or more WEBVIEW contexts.

34. How do you switch to a WebView?

Get the available contexts from the driver, identify the correct WebView context, and switch to it using the client API. The exact method depends on the language client.

35. What is the difference between native and web automation?

Native automation locates and interacts with platform UI elements. Web automation interacts with DOM elements inside a browser or WebView using web-style locators.

Testing and Debugging

36. How do you wait for an element?

Use explicit waits that poll for a meaningful condition, such as visibility or clickability, instead of fixed sleep calls. For example, in Java with Selenium’s wait utilities:

new WebDriverWait(driver, Duration.ofSeconds(10))
    .until(ExpectedConditions.visibilityOfElementLocated(
        AppiumBy.accessibilityId("welcome")
    ));

37. What is the difference between implicit and explicit waits?

An implicit wait applies broadly to element lookups. An explicit wait waits for a specific condition. Explicit waits usually make test intent clearer; mixing wait strategies can lead to confusing delays.

38. How do you take a screenshot?

Use the client’s screenshot API, such as Selenium’s TakesScreenshot interface in Java. Screenshots are useful for failure reports and debugging.

39. How do you handle app installation and launch?

You can provide an app path in capabilities or use driver-supported commands to install, activate, or launch an app. Exact APIs differ by driver and client.

40. How do you reset an app between tests?

Options include reinstalling the app, clearing app data, using reset capabilities, or creating a fresh test state through app APIs. Choose a strategy that keeps tests independent without adding unnecessary setup time.

41. How do you run tests on multiple devices?

Run separate Appium sessions against separate devices or simulators. Configure unique device identifiers and, where required, unique ports and other per-session resources.

42. How do you debug an Appium test failure?

Check the client exception, Appium server log, driver log, device log, capabilities, app state, and locator results in Inspector. Confirm the device and platform prerequisites are healthy.

43. What is Appium Doctor?

Appium Doctor is a diagnostic command provided by some drivers or extensions to check whether prerequisites are configured correctly. For example:

appium driver doctor uiautomator2

Availability depends on the installed extension.

44. What are Appium plugins?

Plugins extend or modify Appium server behavior. They are optional and installed separately from drivers. Plugin overview

Appium 2 and Best Practices

45. What changed in Appium 2 compared with Appium 1?

Appium 2 separated drivers and plugins from the server installation, introduced extension management, and changed some defaults and capability conventions. Migration may require updating server URLs, capabilities, and driver installation. Migration guide

46. Why do Appium capabilities use the appium: prefix?

W3C WebDriver requires vendor-specific extension capabilities to use a namespace. Appium uses appium: for its capabilities.

47. What is parallel execution in Appium?

Parallel execution runs multiple sessions at the same time on different devices or simulators. It requires managing unique device identifiers and any driver-specific ports or resources to prevent sessions from conflicting.

48. How do you make Appium tests more reliable?

Use stable accessibility identifiers, explicit waits, independent test data, clear setup and cleanup, and consistent device configurations. Avoid fixed sleeps and brittle hierarchy-based locators.

49. What are common causes of Appium test failures?

Common causes include incorrect capabilities, missing driver or SDK prerequisites, unavailable devices, stale or unstable locators, app startup delays, permission dialogs, and mismatches between client, server, and driver versions.

50. What is the difference between a real device, emulator, and simulator?

A real device is physical hardware. An emulator imitates Android hardware and software. An iOS simulator runs an iOS-like environment on macOS but does not reproduce every behavior of a physical device.

For version-specific behavior, use the documentation for the installed Appium server and driver. Appium’s drivers and plugins are managed separately from the server, so server version alone does not determine every available command.

Behavioral Interview Questions for a Software Tester

These questions help interviewers understand how you communicate, solve problems, manage priorities, and work with a team. Use the STAR approach to structure answers: Situation, Task, Action, Result. Keep the focus on what you did and what you learned.

Quality and Problem-Solving

1. Tell me about a time you found a serious defect close to a release.

Explain how you assessed its impact, gathered evidence, informed the team, and helped decide what to do next.

2. Describe a difficult bug you investigated. How did you find the cause?

Walk through how you reproduced it, narrowed down the conditions, collected logs or other evidence, and confirmed the root cause.

3. Tell me about a time a bug was hard to reproduce.

Describe how you compared environments and test data, tried different steps, and worked with others to capture the issue.

4. Give an example of when you prevented a defect from reaching users.

Share what you noticed, how you verified the risk, and how the team addressed it.

5. Tell me about a time you had to test a feature with unclear requirements.

Explain how you identified the gaps, asked focused questions, documented assumptions, and tested the agreed behavior.

6. Describe a time your testing uncovered a gap in the product or requirements.

Explain what was missing, how you raised it, and what changed as a result.

7. Tell me about a mistake you made in testing. What did you learn?

Choose a real example. Take responsibility, describe how you corrected it, and explain what you changed to reduce the chance of it happening again.

Communication and Collaboration

8. Describe a time a developer disagreed with a bug you reported.

Explain how you kept the discussion constructive, shared clear reproduction steps and evidence, and reached a decision together.

9. Tell me about a time you had to explain a technical issue to a non-technical person.

Describe how you focused on user impact, used clear language, and checked that the person understood the issue.

10. Give an example of how you worked with developers to improve quality.

Discuss how you collaborated during planning, development, reviews, or debugging—not only after a feature was complete.

11. Tell me about a time you gave or received difficult feedback.

Explain how you listened, responded professionally, and used the feedback to improve your work or communication.

12. Describe a time you helped a teammate.

Share what they needed, how you supported them, and what the team achieved.

13. Tell me about a time you had to raise a quality concern that others did not initially share.

Explain how you presented the evidence, described the risk, and helped the team make an informed decision.

Priorities and Adaptability

14. Tell me about a time you had several testing tasks with competing deadlines.

Describe how you assessed risk, agreed on priorities, communicated trade-offs, and tracked what still needed coverage.

15. Describe a time requirements changed late in a project.

Explain how you adapted the test plan, identified affected areas, and communicated any risks or schedule impact.

16. Tell me about a time you had limited time to test a release.

Discuss how you prioritized critical user journeys and high-risk areas, and how you made remaining gaps visible.

17. Give an example of when you had to learn a new tool or technology quickly.

Explain how you learned the essentials, applied them to the work, and checked that your approach was effective.

18. Describe a time your test environment or test data caused a problem.

Share how you identified the issue, separated environment problems from product defects, and restored reliable testing.

19. Tell me about a time an automated test or test process failed unexpectedly.

Explain how you investigated whether the issue came from the test, environment, or product, then describe the fix.

Ownership and Improvement

20. Tell me about a process you improved.

Describe the problem, the change you proposed or made, and the outcome. Use measurable results if you have them.

21. Give an example of when you took ownership beyond your assigned tasks.

Explain what needed attention, what action you took, and how you kept the relevant people informed.

22. Tell me about a time you had to make a testing decision with incomplete information.

Explain what you knew, what assumptions you made, how you assessed risk, and when you sought input.

23. Describe a time you advocated for the user.

Share a case where you identified a confusing, inaccessible, or unreliable experience and helped the team address it.

24. Tell me about a time you improved test coverage.

Explain how you identified a gap, chose what to add, and how the new coverage helped the team.

25. How do you respond when a test fails intermittently?

Describe how you gather evidence, assess repeatability, investigate possible causes, and report the issue without assuming it is “just flaky.”

Reflection and Motivation

26. What achievement as a tester are you most proud of?

Choose an example where your work made a clear difference to product quality, users, or the team.

27. What do you do when you disagree with a testing decision?

Explain how you raise your concern with evidence, listen to other perspectives, and support the final decision while documenting risk when needed.

28. How do you stay organized during a testing cycle?

Describe the tools or habits you use to track test progress, defects, dependencies, and open questions.

29. What have you learned from a challenging project?

Focus on a specific challenge, what you changed in your approach, and how you apply that learning now.

30. Why did you choose software testing as a career?

Connect your interest in quality, problem-solving, user experience, or collaboration to a specific example from your experience.

Quick Answer Tips

  • Choose a specific example instead of describing what you would do.
  • Explain your own actions while giving credit to the team.
  • Include the outcome and what you learned.
  • Be honest about challenges and mistakes.
  • Avoid sharing confidential company or customer information.
